# NIRNAY — Decision Register

This register documents all locked architectural, product, and operational decisions governing NIRNAY development.

| Decision ID | Decision | Source | Status | Reason | Engineering Consequence |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **DEC-001** | Platform Name & Positioning: **NIRNAY** ("Right Problem. Ready Pilot. Proven Outcome.") | DOC00 v2.0 | **LOCKED** | Distinguishes platform from simple complaint portals by emphasizing decision quality over complaint volume. | UI branding, documentation, and API schemas use canonical NIRNAY terminology. |
| **DEC-002** | Architecture: **Modular Monolith** | DOC00 v2.0 / DOC02 v1.0 | **LOCKED** | Avoids microservice complexity for prototype/V1 while maintaining strict internal domain module separation. | Backend structured into isolated packages (`core`, `models`, `schemas`, `repositories`, `services`, `routers`, `rules`). |
| **DEC-003** | Frontend Stack: **Next.js App Router + React + TypeScript + Tailwind CSS** | DOC02 v1.0 | **LOCKED** | Provides modern component structure, strict type safety, server rendering, and rapid UI development. | Application located in `apps/web` with strict TypeScript configuration and Tailwind v4. |
| **DEC-004** | Backend Stack: **FastAPI + Pydantic v2 + SQLAlchemy v2 + Alembic** | DOC02 v1.0 | **LOCKED** | High-performance Python async REST framework with automatic OpenAPI schemas and strict data validation. | Application located in `apps/api` with structured dependency injection and Alembic migrations. |
| **DEC-005** | Database: **PostgreSQL 16** | DOC02 v1.0 / `docker-compose.yml` | **LOCKED** | Enterprise-grade relational integrity for commitments and JSONB support for flexible evidence payloads. | Executed via Docker Compose (`nirnay-postgres`) on port 5432; accessed via `psycopg` driver. |
| **DEC-006** | P1 Mechanism: **Simple Structured Qualification Workflow** | TRL3 Report / DOC01 v1.0 | **LOCKED** | TRL3 benchmark showed simple structured workflow provides high recall without complex heuristic bloat. | Qualification gate evaluates 4 explicit routes (`SERVICE`, `CLARIFY`, `RESEARCH_REVIEW`, `INNOVATION_CHALLENGE`). |
| **DEC-007** | P2 Mechanism: **Custom Dependency Integrity Engine** | TRL3 Report / DOC01 v1.0 | **LOCKED** | TRL3 validation proved automated dependency invalidation is the strongest core differentiator. | Versioned commitments with automated recalculation of dependent readiness decisions (`REVIEW_REQUIRED`). |
| **DEC-008** | P3 Mechanism: **Simple Structured Evidence & Outcome Workflow** | TRL3 Report / DOC01 v1.0 | **LOCKED** | Standardized baseline, target, metric, and reviewer fields prevent false success claims. | Evidence plans and observation logs stored with strict metric schema and publication permissions. |
| **DEC-009** | Security Gate: **Human Authorization Mandatory for `PILOT_READY`** | DOC00 v2.0 / DOC01 v1.0 | **LOCKED** | Prevents AI or automated heuristics from falsely authorizing field pilots without accountability. | Transition to `PILOT_READY` requires explicit, signed human approval from Problem Owner or Coordinator. |
| **DEC-010** | Data Disclosure: **Synthetic Demo Data Explicitly Flagged** | TRL3 Report / DOC00 v2.0 | **LOCKED** | Prevents misrepresenting test/demo data as live Government of Jharkhand deployments or outcomes. | All seeded data includes `is_synthetic: true`; backend/frontend headers reflect `DEMO_MODE=true`. |
| **DEC-011** | Access Control: **Demo Role Switcher Decoupled from Production Auth** | DOC00 v2.0 / DOC02 v1.0 | **LOCKED** | Allows seamless multi-stakeholder testing during reviews without compromising security architecture. | Role switcher operates via mock request headers/session context, separated from JWT auth logic. |
| **DEC-012** | Lifecycle Decoupling: **Operational Status Decoupled from Evidence Conclusion** | DOC01 v1.0 | **LOCKED** | Completing a pilot does not equal proving social impact. | Field lifecycle (`PLANNED`, `ACTIVE`, `COMPLETED`, `STOPPED`) is strictly separated from outcome status (`NOT_REVIEWED`, `VALIDATED`, `ITERATE`, `INCONCLUSIVE`). |
| **DEC-013** | Scoring Integrity: **No Arbitrary AI "Genuineness" or "Readiness" Percentages** | DOC00 v2.0 / DOC01 v1.0 | **LOCKED** | Black-box percentage scores create false confidence and lack auditability. | Readiness evaluated strictly via deterministic boolean checklist of required conditions and commitments. |
